# 交接说明（师兄阅读指南）

## 一、先看哪些文件

1. `README.md` —— 系统组成、数据流、已完成/未完成总览（20 分钟内读完）。
2. 本文件 —— 下面四节的"能用/不能用"清单。
3. `docs/实验进度.md` —— 每条结论都注明原始日志文件名，方便你自行复核。
4. `docs/文件清单.md` —— 每个文件来自哪里、版本依据（SHA256）、验证状态。
5. `scripts/hololens_hand_step_5cm.py` —— 唯一实机运动验证过的程序，建议先读它
   （413 行，注释完整），再读 `scripts/hololens_robot_control.py`（连续控制的研发状态机）。

## 三、实时跟随还缺哪些环节

1. **驱动队列行为未核实**（连续控制锁定的直接原因）：rm_driver `movel_cmd` 订阅队列
   （ParametersQoS 深度 10）在 block=1 阻塞回调期间会堆积；停止后已排队命令是否被丢弃
   或恢复执行，SDK 为编译库、驱动源码无清队逻辑——需实机核实后才能解锁 `--enable-motion`。
2. **松手→可靠停止→重新锚定→继续跟随**的完整实机闭环未验证（离线状态机已覆盖，实机未跑）。
3. **实时周期/延迟/工作空间边界**未验证。
4. **头显状态回传**未实现。
5. HoloLens 与 RML63 基坐标的**真实标定**未完成（现有 `docs/hololens_calibration.md` 仅为
   虚拟测试与样本准备；单次实验绕开标定，只做单轴映射 Unity +Y→Base +Z）。

## 四、哪些脚本不能直接用于连续控制

- `experimental/follow_target_core.py`、`experimental/follow_command_gate.py`：
  **离线研发模块，不是控制器**。未接入 ROS/驱动、未实机，直接改一改就上机会出问题
  （例如工作空间边界需要在 Base 坐标下实机勘测，不能凭空设定）。
- `legacy/hololens_hand_step*.py`、`hololens_single_trigger.py`、`robot_stop_check_v2.py`：
  单次实验程序，**不是**实时跟随，绝不连续重跑累计位移。
- `scripts/hololens_robot_control.py`：状态机离线完备，但运动入口锁定，且"停止已确认"
  的判定依赖关节速度上报使能（joint_speed_enable）与实机标定的阈值。

## 五、实机前必须逐项核实（解锁运动的前提，未完成）

- [ ] rm_driver 订阅队列：停止后已排队 Movel 是否执行（用 `ros2 topic info --verbose` 与单命令实验核实）。
- [ ] 控制器 UDP 上报 `joint_speed_enable` 运行时确实使能（`/rm_driver/get_realtime_push_cmd` 查询）。
- [ ] 静止阈值标定：位置 0.5mm、速度 0.1 RPM 需按噪声与最小运动速度实测调整。
- [ ] 现场：两人在场、急停可用、工具上方空间确认。
- [ ] Unity 端源码补充入库（Windows 工程，见文件清单未收录节）。

## 六、运行时的边界提醒（写在这里，比藏在代码注释里更醒目）

- 停止请求**不是**即时物理停止；停止回执延迟**不是**制动时间。
- `move_stop_result=true` 只表示接口返回成功；`movel_result=false` 不能独立证明停止成功。
- 目标限幅（clamp_radius/limit_step/max_offset）限制发送值，**不保证**实际位置绝不越界。
- SIGKILL 无法由进程内处理兜底，唯一保障是人工急停。
